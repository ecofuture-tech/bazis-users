# bazis-users 2.9.0

Requires Bazis 2.11.

## Security

- **The other routes linked and showed the users the user routes hide (bazis-users 2.4.0
  to 2.8.0, with Bazis 2.7 and later).** `UserRouteSet` (`bazis.contrib.users.router`)
  restricted only its own list and items (`get_queryset`: a user who is not staff sees only
  himself), not `restrict_queryset`, which the core calls on the default route of the user
  model for the relationships of the writes, `included` and the filters through a relation
  of the other routes. So a user who is not staff linked any user he cannot see into a
  relationship (a many-to-many of watchers, a foreign key: 200), saw the other users in
  `included` (their attributes) and found them by a filter through a relation
  (`filter=watchers__username=...`). `UserRouteSet.restrict_queryset` now has the rule of
  the user routes: staff every user, another authenticated user only himself, nobody
  without authentication (a route without a user takes the user of the request,
  `UserMixin.CTX_USER_REQUEST`); `get_queryset` applies it. Linking another user is 403
  `ERR_RELATION_ACCESS`; the users already linked stay (only the users whose link changes
  are checked), the relationship keeps their identifiers, `included` leaves them out. On
  older versions, define the default route of the user model in the project (a subclass
  of `UserRouteSet` with `default_route = True`, or a `PermitRouteBase` route) with a
  `restrict_queryset` of this rule written out (`UserRouteSet` has none to call with
  `super()` there).

## New

- `bazis.contrib.users.service.get_request_tokens`, a FastAPI dependency: the tokens of the
  request undecoded (`RequestTokens`: `header`, `param`, `cookie`, and `token`, the one the
  request presents: the query parameter, else the bearer token, else the cookie), and
  `session_token_data(token)`, the data of a session token as `get_token_data` gives it
  (`{}` without a token or for a token without expiration, 401 for an expired or invalid
  one). bazis-authing 2.7 reads its tokens with them instead of a copy of the parameters
  and the order. `get_token_data` keeps its parameters (bazis-authing 2.6 calls it with
  the three tokens); in 3.0 it takes `RequestTokens`.

- `bazis.contrib.users.models_abstract.in_user_language(user)`: `translation.override`
  in the language of the user (`user.language` of `UserLanguageMixin`, else
  `LANGUAGE_CODE`, also for a user model without the mixin), for the work done for a user
  outside his requests. It replaces the recipe
  `translation.override(user.language or settings.LANGUAGE_CODE)` of the guide; bazis-notify
  uses it.
- `UserMixin.authenticated_user(user=None)`: the user if he is authenticated, without one
  the authenticated user of the request (`CTX_USER_REQUEST`), else None. The
  `restrict_queryset` of `UserRouteSet` and of bazis-notify start with it (the core also
  calls it on a route class without a user).

## Breaking changes

- A user who is not staff links only himself into a relationship to the users and sees only
  himself in `included`, through every route of the project whose user model has
  `UserRouteSet` (or a subclass, such as `UserWsRouteSet` of bazis-ws) as its default
  route. A project whose users pick other users subclasses `UserRouteSet` with
  `default_route = True` and widens `restrict_queryset` for `CrudAccessAction.VIEW` only,
  calling `super().restrict_queryset(...)` for any other operation: a reverse relation to
  the users (`Role.users` for `User.roles`) changes the users it links and is checked with
  `change` (the recipe is in the guide). Projects with bazis-permit protect the users with
  a `PermitRouteBase` route, whose `restrict_queryset` applies.
