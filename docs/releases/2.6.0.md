# bazis-users 2.6.0

Requires Bazis 2.6.

## Features

- **The OpenAPI schema tells a client generator which operations need the token.**
  FastAPI already declared the `OAuth2PasswordBearer` scheme and a `security` entry on every
  operation that reads the token, as if the token were always mandatory. Now the routes that
  serve anonymous requests (`UserRouteBase`, so also the routes of bazis-permit) declare
  `security: [{"OAuth2PasswordBearer": []}, {}]` (the token is optional) and only the routes
  that require it (`UserRequiredRouteBase`, `UserRouteSet`) keep
  `[{"OAuth2PasswordBearer": []}]`.
- **The 403 errors are documented** where the routes answer them: `action_dict_data` of
  `UserRouteBase` (staff only) and the create, update and delete operations of
  `UserRouteSet` (staff only, the privileged fields of a superuser).
- **The 401 error is documented** (`SchemaErrors`, the JSON:API errors) on the operations
  of the user routes (an invalid or expired token, a missing one on the required routes)
  and on the token endpoint (wrong credentials).
- `UserOpenApiMixin` (`bazis.contrib.users.routes_abstract`) does it for a route class of
  your own that injects `get_user_required` directly: inherit it and set
  `auth_required = True`.
