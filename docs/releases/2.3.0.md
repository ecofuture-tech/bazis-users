# bazis-users 2.3.0

Requires Bazis 2.3 (Django 6.1, FastAPI 0.142).

## Security

- `python-jose` (unmaintained, with known vulnerabilities, and no longer installed by
  Bazis) is replaced with `PyJWT`. Tokens issued by earlier versions stay valid.
- A session token must contain `exp` and `sub`: a token without expiration identified
  its user forever. A token without expiration (e.g. the authorization store token of
  bazis-authing, which uses the same cookie) now identifies nobody: the request is
  anonymous. Tokens now also carry `iat`, which is not verified (clock skew).
- `BAZIS_JWT_SESSION_ALG` accepts only `HS256`, `HS384` and `HS512`: tokens are signed with
  `SECRET_KEY`, so any other value was a misconfiguration. Other values fail at startup.
- `UserRequestMiddleware` resets the user context after the response. Under a WSGI server
  with worker threads, the user of one request stayed in the context of the thread, so
  a later request of another user (or an anonymous one) in the same thread could be
  attributed to the previous user (e.g. as `author` by bazis-author).

## Other changes

- New `bazis.contrib.users.service.decode_token(token)` verifies a session token
  outside of a request.
- The README referred to a non-existent module `bazis.contrib.users.services` and to
  a `user_id` claim; it is `service`, and the username is in `sub`.
- Dependencies: `bazis>=2.3.0`, `PyJWT>=2.10`, `python-multipart>=0.0.18`.
- Tests for valid, expired, foreign-key, unsigned, `exp`-less and `sub`-less tokens,
  inactive users and the middleware.
- CI runs the tests on Python 3.12–3.14 and with the lowest allowed dependency versions;
  releases are made with the Release workflow (see `CLAUDE.md`).
