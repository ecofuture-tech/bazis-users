# bazis-users 2.7.0

Requires Bazis 2.6. Breaking: the user model of a project gets a field, run
`makemigrations`.

## Features

- **The language of a user.** `UserAbstract` has the field `language`: the language the user
  has chosen, a code of `LANGUAGES`, blank when he has chosen none (the default). Its
  choices are the languages of the project through a callable (`language_choices`), so a
  change of `LANGUAGES` needs no migration, neither of the project nor of the package. The
  user reads and changes it himself with the user routes (the attribute `language`,
  `PATCH /user/{id}/`); bazis-front adopts it at a login and saves the language of its
  interface there, so the choice follows the user to his other devices. The language of a
  request is still `?lang` or `Accept-Language` (the core); work done for a user outside his
  requests (e-mails, background tasks) can use `user.language`.

## Upgrading

- Run `python manage.py makemigrations` for the user model of the project (the
  `AddField` of `language`; the bundled `bazis.contrib.users.models.User` has the migration
  `0003_user_language`).
- The schemas list the languages of the project (`enum`), but the core does not reject
  another value on a write: a client sends a code of `LANGUAGES`.
