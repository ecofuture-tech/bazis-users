# bazis-users 2.7.0

Requires Bazis 2.6.

## Features

- **The language of a user.** `UserLanguageMixin` adds the field `language` to a user model:
  the language the user has chosen, a code of `LANGUAGES`, None when he has chosen none (the
  default). It is opt-in: `UserAbstract` is unchanged, so the user models of the projects
  and of the samples of the other packages need no migration. The user model of the
  package (`bazis.contrib.users.models.User`) has it, with the migration
  `0003_user_language`. Its choices are the languages of the project through a callable
  (`language_choices`), so a change of `LANGUAGES` needs no migration. The user reads and
  changes it himself with the user routes (the attribute `language`, `PATCH /user/{id}/`).
  Saving stores the code of `LANGUAGES` (`ru` of `ru-RU` or `RU`, None of a blank value);
  another language is a 422 with the pointer `/data/attributes/language`, whatever route
  saves it. bazis-front detects the field, adopts it at a login and saves the language of
  its interface there, so the choice follows the user to his other devices. The language
  of a request is still `?lang` or `Accept-Language` (the core); work done for a user
  outside his requests (e-mails, background tasks) can use `user.language`.

## Using it in a project with its own user model

Add the mixin and run `python manage.py makemigrations`:

```python
from bazis.contrib.users.models_abstract import UserAbstract, UserLanguageMixin
from bazis.core.models_abstract import JsonApiMixin, UuidMixin


class User(JsonApiMixin, UuidMixin, UserLanguageMixin, UserAbstract):
    pass
```
