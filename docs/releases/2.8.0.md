# bazis-users 2.8.0

Requires Bazis 2.11.

## Security

- **`UserRouteBase` has no `GET /{item_id}/dict_data/`.** It answered staff
  (`is_staff`) all the attributes of an item of every route based on `UserRouteBase` (so
  every route of bazis-permit), past the `fields` of the route and the field permissions.
  Bazis 2.11 removes the route from `JsonapiRouteBase` for the same reason; this release
  removes the copy that limited it to staff, and its 403 from the OpenAPI operations. It
  requires Bazis 2.11: with an older core, `UserRouteBase` would inherit the unrestricted
  route of the core.

## Breaking changes

- A request to `/{item_id}/dict_data/` is 404. A project that needs such a route defines it
  in its route class and restricts it itself, for example to superusers:

  ```python
  from bazis.core.errors import JsonApi403Exception
  from bazis.core.routes_abstract.initial import http_get

  class DocumentRouteSet(UserRouteBase):
      @http_get('/{item_id}/dict_data/')
      def action_dict_data(self, item_id: str, **kwargs):
          if not self.inject.user.is_superuser:
              raise JsonApi403Exception()
          return self.set_item(item_id).dict_data
  ```

  `JsonApiMixin.dict_data` shows every attribute of the model: do not open it to users whose
  fields a route or a permission hides.
