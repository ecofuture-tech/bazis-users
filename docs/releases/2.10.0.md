# bazis-users 2.10.0

## Changes

- **The routes accept only a code of `LANGUAGES` as the `language` of a user.** Bazis 2.18
  checks the choices of a field on a create and an update, so `PATCH /user/{id}/` with
  `language: "ru-RU"` or `"RU"` is a 422 at `/data/attributes/language` ("Value 'ru-RU' is
  not a valid choice") instead of being stored as `ru`; an unknown language is the same
  422, with this text. `UserLanguageMixin.save()` still stores the code of `LANGUAGES` for
  the code that saves a user (`user.language = 'ru-RU'; user.save()`), and a stored
  language the project no longer has is still left alone by the saves in the code until it
  is changed. A request that sends such a language back, even unchanged, is a 422 now.
- Requires `bazis>=2.18.0`.

## Upgrading

- A client that sends the language of a browser (`navigator.language`) must map it to a
  code of the `enum` of the attribute (the OpenAPI shows it), and one that sends all the
  attributes of a user must not send back a language the project no longer has.
